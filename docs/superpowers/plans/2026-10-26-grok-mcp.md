# Grok MCP Connector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Jake's Grok bot read 9am Crew programming and change future days and cycles through preview → push → undo, over an MCP endpoint inside the app.

**Architecture:** A stateless Streamable HTTP MCP route at `/api/mcp`, wrapped in bearer-token auth. Tokens come from Supabase Auth's OAuth 2.1 server, and the app hosts the consent page. Each request builds a Supabase client that carries the caller's token, so RLS applies exactly as in the builder. Validation runs in TypeScript, shared with the server actions. Push and undo are single Postgres functions (`security invoker`), so each one is all-or-nothing.

**Tech Stack:**
- Next.js 16 App Router (route handlers)
- `mcp-handler@2.3.0`, `@modelcontextprotocol/server@^2`, `zod@^4`
- Supabase (`@supabase/supabase-js` with `auth.oauth`)
- vitest
- PGlite (`scripts/test-db.mjs`)

**Spec:** `docs/superpowers/specs/2026-10-26-grok-mcp-design.md`

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing route or page code (AGENTS.md). Route handlers: `01-app/01-getting-started/15-route-handlers.md`.
- Never use a service-role key. Every query runs through the caller's token and existing RLS.
- No new Vercel environment variables. Use only `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- Only `approved` admins (`profiles.is_admin and profiles.approved`) can use any tool.
- Future only: day writes (put_day, delete_day, put_coach_notes) need `class_date > today` in America/Halifax. Use `todayLocal()` from `src/lib/dates.ts` in TypeScript and `(now() at time zone 'America/Halifax')::date` in SQL.
- Cycle rules:
  - A new cycle must start after today.
  - A cycle that has started (`start_date <= today`) keeps its `start_date`.
  - Only cycles that haven't started can be deleted.
  - Deleting a cycle never touches workouts.
- MCP writes only these workout columns: `title, focus, why, parts, status, updated_at`. Leave `equipment_add`, `equipment_remove`, `clock_plan`, `clock_by` and `clock_for` alone, except when undo recreates a deleted row.
- Do not reject requests that lack an `MCP-Protocol-Version` header (Grok bug). mcp-handler's stateless legacy fallback handles this; Task 2 checks it.
- Public URL: `https://9amcrew.ca`. MCP URL: `https://9amcrew.ca/api/mcp`. Authorization server issuer: `${NEXT_PUBLIC_SUPABASE_URL}/auth/v1`.
- New migration: `supabase/migration-024-mcp.sql`. Jake runs it in the Supabase SQL editor **before** merging the PR that uses it.
- Ship as two PRs into `main`:
  - PR 1: Tasks 1–3, the connection spike.
  - PR 2: Tasks 4–8.
  - Never merge without Jake's OK.
- `npm run build` must pass. It runs vitest, then the db checks, then `next build`.

## Review Focus

1. **Grok sends back a day it read, unchanged.** The day includes gentle lifts like "Goblet squat" that aren't in `movements`. It must validate with no errors and no warnings, and the preview must say "no change." Test: Task 5, `unchanged day round-trips`.
2. **Two changes for the same date (or cycle) in one preview.** This is ambiguous, so the preview must be an error, not "last one wins." Test: Task 5, `duplicate targets`.
3. **A preview is pushed after today has rolled past one of its dates** (previewed at 11 pm, pushed the next morning). The push must refuse. Test: Task 6 db check, `push refuses a day that is no longer future`.
4. **Push or undo is called twice** (Grok retries after a timeout). The second call must fail cleanly with "already pushed" or "already undone", and nothing may be applied twice. Test: Task 6 db check, `double push / double undo`.
5. **A put_day for a date with no workout yet, with coach notes in the same change.** The workout insert must happen before the notes upsert (foreign key). Undo must remove both. Test: Task 6 db check, `create day with notes, then undo`.

### Task 6: Migration 024: change sets, push, undo

**Files:**
- Create: `supabase/migration-024-mcp.sql`
- Modify: `scripts/test-db.mjs` (load the file after 023; add the checks below before the final `console.log`)

**Interfaces:**
- Consumes: the `Op` and `Seen` JSON shapes from Task 5, stored as-is.
- Produces:
  - Table `public.mcp_change_sets` with these columns:
    - `id bigint generated always as identity primary key`
    - `created_by uuid not null default auth.uid() references public.profiles(id) on delete cascade`
    - `created_at timestamptz not null default now()`
    - `status text not null default 'preview' check (status in ('preview','invalid','pushed','undone'))`
    - `summary text not null` (a one-line description for list_pushes)
    - `ops jsonb not null`
    - `seen jsonb not null`
    - `before jsonb`
    - `after_stamps jsonb`
    - `pushed_at timestamptz`
    - `undone_at timestamptz`
  - RLS: admins can select, insert and update their own rows (`created_by = auth.uid()`). There's no delete policy. Update is needed because the functions run as the caller.
  - `public.mcp_push(set_id bigint) returns jsonb` and `public.mcp_undo(set_id bigint default null) returns jsonb`, both `language plpgsql security invoker set search_path = public`.
    - They return `{ ok: true, set_id, days: text[], cycles: bigint[] }` on success.
    - On failure they raise an exception with a plain-English message. The route passes the message to Grok.

**mcp_push(set_id)**, in order and in one transaction:
1. Lock the row (`for update`).
2. Require `is_admin()`, `created_by = auth.uid()`, `status = 'preview'`, and `created_at > now() - interval '24 hours'`. Otherwise raise `already pushed`, `already undone`, `has problems`, or `expired, preview again`.
3. For every op touching a date, require `date > (now() at time zone 'America/Halifax')::date`. Otherwise raise `{date} is no longer in the future`.
4. Stale check: for each date in `seen.days`, the current `workouts.updated_at` must equal the seen value, with null meaning the row must still be absent. Do the same for `seen.notes` against `workout_coach_notes.updated_at`, and for `seen.cycles`. On a mismatch, raise `changed since preview: {list}`.
5. Capture `before`:
